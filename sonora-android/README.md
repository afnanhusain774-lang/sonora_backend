# Sonora

Sonora is an original, responsive music-player web app and installable PWA. It
plays the included original demo recordings and audio files that you import.
Spotify integration uses your own Spotify account, the official Web API, and
Spotify's Web Playback SDK; it does not download Spotify audio or use unofficial
streaming resolvers.

## Run the web app

Python 3 is sufficient to serve the static app locally:

```sh
python3 -m http.server 8765 -d web
```

Open [http://localhost:8765/](http://localhost:8765/). Use HTTPS or localhost
for Spotify authentication, service workers, and PWA installation.

## Spotify setup

1. Create a Spotify developer application and copy its **Client ID**.
2. Open Sonora's **Settings → Spotify Web API**, enter the Client ID, and save.
3. Add the exact redirect URI shown by the page to the Spotify application's
   Redirect URIs. For the local command above, it is
   `http://localhost:8765/`.
4. Connect your account. Catalog search and metadata use the official Spotify
   Web API. Web playback requires Spotify Premium and an eligible browser.

The app uses Authorization Code with PKCE and never asks for a client secret.
Spotify controls its own stream quality and available devices; Sonora cannot
force a bitrate. Spotify does not expose a general synchronized-lyrics endpoint
to this client, so timed lyrics are imported as `.lrc` files for local audio.

## Included features

- Responsive dark UI, search for Spotify tracks/albums/artists, saved Spotify
  playlists, liked tracks, a local library, player controls, seeking, volume,
  and crossfade for local audio.
- Phone layout replaces the top search bar with Home, Search, Library, and Reels
  tabs, plus a compact player above the navigation; desktop navigation remains
  available on larger screens.
- Tap the mini-player's song details to open Now Playing, with full-size artwork,
  transport and seek controls, saved-track actions, sharing, and synchronized
  imported lyrics for local audio.
- IndexedDB storage for user-imported audio, timed `.lrc` files, preferences,
  and listening history. Local playback is offline after import; browser/platform
  support determines whether FLAC can be decoded.
- A service worker caches the app shell and six original, 24-second demo tracks.
  Spotify audio is not cached.
- Discover Weekly (up to 50 unique search results) and 30 genre/mood mixes use
  Spotify catalog search and the user's configured taste preferences; they are
  not Spotify-curated playlists.
- A vertical scroll-snap Reels feed, track sharing, browser Document
  Picture-in-Picture where supported, and device controls through Spotify's
  official API. Other Sonora tabs can exchange playback state on the same
  browser origin.
- Synchronized lyrics for local audio when an `.lrc` file is imported.

Remote friend activity needs an account/backend service and is not included.
Cross-tab activity is local to the same browser origin. Browser Picture-in-Picture
is not an Android system overlay and may not float above games. Capacitor packages
the app as an Android app, but Spotify's own Premium/browser/device restrictions
still apply.

## Project structure

```text
web/
  index.html
  manifest.webmanifest
  sw.js
  assets/
    audio/                 # Original, offline demo recordings
    icon.svg
  src/
    app.js                 # App state, event handling, feature integration
    data.js                # Demo catalog, 30 mix definitions, Spotify scopes
    utils.js               # Formatting, Spotify normalization, LRC parser
    api/spotify.js          # Spotify PKCE, Web API, Web Playback SDK
    audio/engine.js         # Local audio, volume, seek, crossfade
    state/store.js          # State helper and same-origin tab session
    storage/database.js     # IndexedDB library/settings/history
    ui/lyrics.js            # Synchronized local LRC view
    ui/render.js            # Pages and reusable UI rendering
    styles.css
capacitor.config.json
package.json
```

## Build an Android APK with Capacitor

Node.js/npm, Android Studio, and an Android SDK are required. The Capacitor
Android project is configured to use `capacitor-android/`, leaving the existing
native prototype in `android/` untouched.

```sh
npm install
npx cap add android
npx cap sync android
npx cap open android
```

In Android Studio, build the APK using **Build → Build Bundle(s) / APK(s) →
Build APK(s)**, or use the generated Gradle project:

```sh
cd capacitor-android
./gradlew assembleDebug
```

The debug APK is written to
`capacitor-android/app/build/outputs/apk/debug/app-debug.apk`. For subsequent
web changes, run `npx cap sync android` before building again.

## Existing native prototype

The separate `android/` directory remains the original native Android prototype.
Its six demo WAVs are generated by `scripts/generate_demo_tracks.py`. To run it,
open this folder in Android Studio and launch the `app` configuration on a phone
or emulator.
